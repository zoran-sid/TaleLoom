# TaleLoom 织境：项目说明

## 一句话

**一个数据驱动的文字冒险引擎：剧情写在 JSON 剧本里，玩法写成可插拔的机制插件；同一 Python 核心支持桌面 GUI 与网页试玩，运行两个原创剧本。**

当前已实现 CLI 骨架。2026-11-08 更新桌面 GUI、网页与自动发布要求，实施顺序和验收见 [GUI／网页实施要求](gui-web-plan.md)。

## 为什么做引擎而不是做一个游戏

只写一段固定故事，代码里会塞满 `if 选了A: print(...)`，展示出来只是“一个故事能跑”。做成引擎后，项目的设计价值体现在三处：

1. **内容与代码分离**：剧本作者只写 JSON，不改 Python。新增剧本不需要动引擎。
2. **玩法可扩展**：推理搜证、道具解谜这样的玩法是插件，剧本在 `"mechanics"` 里选择启用。插件向引擎注册新的条件、效果和玩家命令。
3. **可验证**：剧本在运行前做静态校验（跳转目标、物品、线索、可达性、结局），通关脚本可以自动回放，CI 每次提交都检查两个剧本的全部结局。

演示时用两个剧本证明第 1、2 点：

| | 剧本 A《雾港旧案》 | 剧本 B《深空回声》 |
| --- | --- | --- |
| 类型 | 推理搜证（民国港口旅馆命案） | 资源管理与道具解谜（太空站逃生） |
| 启用插件 | `mystery`：线索、搜证、审问、指认 | `puzzle`：使用、组合道具 |
| 引擎核心能力 | 条件选项、一次性选项、多结局 | 每回合变量（氧气倒计时）、触发器、多结局 |
| 玩家核心操作 | 搜查地点 → 收集线索 → 对质 → 指认凶手 | 搜索物品 → 组合道具 → 在正确地点使用 → 抢在氧气耗尽前逃离 |
| 负责人 | ZC | LQ |

两个剧本目前是 v0 序章（各约 6–8 个场景，全部结局有通关脚本），由负责人扩写。

## 灵感来源与原创性

剧本 A 的玩法参考了国内剧本杀的通用机制（成员提供的参考：《雪乡连环杀人事件》的几篇复盘文章与产品页）：

- 线索分轮发放、按地点搜证、对已发现线索做“深入搜证”；
- 角色隐藏身份与中途反转；
- 投凶阶段按证据组合决定结局，包括“指认对了但证据不足”的结局。

我们只借鉴**机制**，故事、人物、地点和文字全部原创，不改编任何现有剧本的情节（课程第 3 页要求作品原创；四篇参考资料对同一剧本的剧情说法也互相矛盾，不适合作为依据）。报告中引用这些资料时只说明“玩法借鉴自剧本杀”。

## 用户与使用场景

- **玩家**：目标是在 VS Code 运行 `main.py` 后打开独立窗口，或访问网页直接游玩；通过按钮、背包、线索与存档界面完成两个剧本。当前 CLI 继续支持编号和中文短句操作。
- **剧本作者**：不会编程也能按 [剧本格式](story-format.md) 写 JSON，用 `python main.py validate` 立即看到哪里写错。
- **开发者**：为新玩法编写插件及结构化动作／展示数据，界面通过统一约定接入；各模块用固定样例独立开发和测试。

## 范围

- 必做：简洁桌面 GUI、两个原创剧本、可点击的完整游玩流程、存档、回放测试、CI；同一核心的网页试玩和 Cloudflare 监听 GitHub 推送自动部署。
- 实施顺序：共享契约 → 桌面最小闭环 → 浏览器兼容验证 → 网页界面／存档 → 自动发布。网页为明确交付目标；当前尚未实现。
- 后续可选：背景／人物图片、音效、动画和更复杂的交互；展示模块独立，素材可选，保持文字版可玩。
- 首版采用单人、无账号、本机／浏览器存档。跨设备云存档、多人联机和 AI 实时生成剧情不在当前交付范围。AI 用于开发过程并记录在 [AI 使用记录](ai-usage.md)。

## 运行环境

Python 核心与桌面运行使用 Python 3.10+ 标准库；桌面 GUI 需要 Tcl/Tk。入口 `main.py`，说明见 [README](../README.md)。网页采用 HTML/CSS/JavaScript + Pyodide，运行时和构建依赖单独锁定；Cloudflare Workers Static Assets 与 Workers Builds 负责托管和自动发布。标准库限制属于本项目选型，课程允许 CLI 或 GUI，并要求外部资源正确引用。
