# GUI、网页试玩与自动部署要求

更新日期：2026-11-08。来源：总设计者新增要求。共享接口与固定样例已提供；当前分支进一步提供网页序章、v0 兼容会话及 Cloudflare 构建／部署命令。正式桌面 GUI、成员扩展模块与首次云端发布继续按本计划完成。

## 0 当前部署基础与成员衔接

总设计者要求先达到可部署阶段，同时保持小组任务。网页以独立 `web/runtime/` 和可替换 `web/preview/` 接入现有核心，会话统一由 `taleloom/session_factory.py` 创建；没有修改成员的引擎、加载、解析、存档或剧本文件。`main.py` 仍保留现有入口。详细配置与替换点见 [部署指南](cloudflare-deploy.md)。下面的正式模块归属继续有效，v0 兼容层不代表已完成成员任务。

## 1 交付目标与优先顺序

1. **桌面游玩**：在 VS Code 中运行根目录 `main.py`，无参数启动即弹出独立 GUI，选择剧本后开始游戏。采用 Tkinter + ttk，视觉以简洁、易读的文字冒险为主。
2. **网页游玩**：玩家访问固定网址即可开始游戏，无需安装 Python。网页与桌面共用 Python 引擎、插件、JSON 剧本及存档数据格式。
3. **自动发布**：Cloudflare 连接 GitHub 仓库并监听推送，自动执行检查、构建与部署。`main` 对应正式试玩，`develop` 与成员分支对应预览；日常发布只需按协作流程合并代码。
4. **异步扩展**：后续背景图、人物图、音效及新玩法按独立模块接入，各成员可用固定示例数据开发和测试。

共享接口先行；本轮先完成现有序章的网页部署基础，桌面最小闭环由对应成员继续开发。网页是明确的交付目标；图片、音效和复杂动画是后续可选扩展，不阻塞文字版交付。

## 2 玩家体验与验收

- 起始页列出剧本、简介和开始／继续入口。
- 游戏页显示场景标题、正文、行动按钮，以及背包、已发现线索、回合和剧本声明可见的资源。
- 选项、使用／组合道具、搜证、审问、指认、存读档、重新开始、返回首页均有可点击入口。两个剧本能够全程不用输入命令完成。
- 指认、覆盖存档和重新开始等操作在有实际不可逆影响时给出确认；普通查看操作直接响应。
- 长文本可滚动，窗口缩放后文字与按钮仍可用；网页同时覆盖桌面和手机宽度，提供清晰的键盘焦点。
- 界面刷新、查看背包、打开线索页和调整窗口不消耗回合、不改变随机状态、不重复触发进入场景事件。
- 每次操作串行执行；操作处理中禁用会重复提交的控件，旧响应不能覆盖较新的游戏状态。
- 结局页显示结果并提供继续阅读、读档、重开和返回首页。结束后不再提交推进剧情的操作。
- 保留 CLI 的开发、回放和排错能力。GUI 实现时另行明确 CLI 游玩参数，同时兼容现有 `validate`、`replay` 及已合入的开发命令。

## 3 技术路线：一个 Python 核心，两个展示端

```text
桌面：main.py → Tkinter GUI ─┐
                            ├→ 会话控制／展示数据 → Engine → 规则与插件
网页：HTML/CSS/JS → Web Worker┘                         ↑
                   + Pyodide                    共用 stories/ JSON

存档数据编码／校验 → 桌面文件存储 或 浏览器存储／JSON 导入导出
```

- 桌面和 Python 核心继续使用 Python 3.10+ 标准库。Tkinter 需要演示电脑的 Python 带 Tcl/Tk 支持，交付前验证 Windows 和 macOS 的启动与中文显示。
- 网页使用 HTML/CSS/JavaScript 展示界面，通过 **Pyodide 在浏览器的模块型 Web Worker 中运行同一份 Python 核心**。JavaScript 负责展示、消息传递和浏览器存储；游戏规则只在 Python 中维护。
- Cloudflare **Workers Static Assets** 托管网页、运行时及打包后的引擎和剧本；运行时资源优先随发布版本托管，锁定版本并遵守平台文件大小限制。首屏展示加载状态、失败原因与重试入口。
- Pyodide 是网页端的额外运行时依赖，需要记录版本、许可证及来源；它不成为桌面端安装依赖。网页构建工具同样单独记录和锁定版本。
- 引擎和插件不得依赖 Tkinter、DOM、浏览器存储或 Cloudflare SDK。桌面界面延迟导入，网页包仅包含所需核心模块、插件和剧本。
- 先用两个现有序章验证 Python 导入、全部结局回放、状态序列化、随机状态恢复和存档指纹在 Pyodide 中的兼容性，作为网页实施的第一个里程碑。
- 首版为单人、无账号游戏。进度保存在当前浏览器，可导出／导入 JSON；不会自动跨设备同步。清除网站数据可能删除本机进度，界面提供导出入口。
- 桌面存档与网页存档使用同一版本与校验规则，存储方式独立。浏览器内的临时虚拟文件系统不能作为刷新后仍可恢复的唯一存档。

## 4 供异步开发的共享约定

类型与方法名已在 `taleloom/ui_contract.py` 明确定义，调用示例与行为见 [接口约定第 6 节](contracts.md#6-桌面网页共享接口-v1)。`tests/ui_fakes.py` 提供可运行测试替身。下表为正式模块任务；网页部署基础暂由独立 v0 兼容层承接现有引擎与存档。

| 数据／能力 | 约定 | 负责 |
| --- | --- | --- |
| 展示快照 | JSON 可序列化；场景 ID／标题／正文、稳定 ID 的行动、玩家可见物品与线索、公开资源、结局和可选素材引用 | YHT 定义类型，ZQO 生成 |
| 操作提交 | 传稳定 ID 和结构化参数；支持场景选择及插件操作，执行时重新验证合法性 | ZQO、插件作者 |
| 纯读取 | 多次读取同一状态得到相同展示数据；不修改状态，不抽随机数；随机结果在实际行动时生成并保存 | ZQO |
| 插件展示 | 提供玩家已知内容、可尝试动作及参数候选；隐藏未发现线索、配方答案和结局判定规则 | ZC、ZRS |
| 会话控制 | 新游戏、提交操作、恢复状态、取得快照；统一错误结果；桌面和网页共用 | ZQO |
| 存档边界 | 将编码／解码／版本校验与文件读写分开；浏览器存储不进入引擎 | LQ |
| 示例与测试 | 固定示例快照、命令及预期结果，能够独立驱动 GUI 和网页；集成测试覆盖真实剧本 | 各模块、ZC |

快照隐藏剧透是展示要求。客户端随包分发完整剧情，不承诺阻止玩家查看源文件中的剧情数据。

共享契约提供可运行测试替身、明确接口和样例测试，保留已有 CLI／回放调用。网页 v0 兼容适配已通过现有序章测试。真实适配器须在后续实现 PR 中通过行为约定和真实剧本测试。后续成员分别开发，不等待完整剧情或最终美术。新增玩法必须同时提供操作描述与对应的图形交互；全新交互形式在独立界面组件中实现。

## 5 目录归属与工作量

`ui_contract.py` 与 `tests/ui_fakes.py` 已提供；ZC 的运行桥接与构建已落地，网页临时界面放在 `web/preview/`。下表中的其余正式模块路径为实现计划，现有模块归属保持不变。共用目录按具体文件划分，避免多人同时修改入口。

| 成员 | 新职责与计划路径 | 与已有任务的关系 |
| --- | --- | --- |
| YHT | `ui_contract.py` 中展示数据类型；`loader.py`／`validator.py` 的可选展示字段校验 | 保留已完成加载／校验工作，新增字段兼容已有剧本 |
| ZQO | `taleloom/session.py`、`taleloom/presentation.py`；快照、会话控制、插件展示接口、纯读取 | 优先共享接口，随机／变体与显示协同设计 |
| ZRS | `taleloom/gui/` 桌面界面；`web/index.html`、`web/styles/`、`web/ui/` 网页展示；道具交互 | GUI 与网页通用操作优先，终端颜色、补全、复杂句式降为可选 |
| ZC | `main.py`、`.vscode/launch.json`、`taleloom/session_factory.py`（桌面与网页共用的会话入口）；`web/runtime/` 的 Pyodide 桥接；推理展示；`tools/build_web.py`、Cloudflare 配置与发布整合 | 统筹契约、启动、网页桥接和部署，先用现有序章验证 |
| LQ | `save.py` 数据编码与存储适配；`web/storage/`；存档互通与浏览器回放验证 | 保留随机探索及剧本 B，提供可独立测试的存档接口 |

`tests/<成员>/` 继续存放各自测试；`tests/integration/` 由 ZC 维护。共享 fixtures 的新增在契约 PR 中统一提交。网页组件使用同一份快照样例；浏览器自动化工具可作为开发依赖，不影响桌面运行依赖。

素材归属：`stories/<剧本>/assets/` 由对应剧本作者维护；主题、图片与音频展示组件归 ZRS。素材字段为可选，缺失时仍能文字通关；路径限于剧本目录，错误引用有明确提示。

## 6 Cloudflare 监听 GitHub 自动部署

**固定发布路线：GitHub 推送 → Cloudflare Workers Builds → 检查与构建 → 自动部署 → 固定网址更新。** 使用 Cloudflare 原生 Git 集成；日常不要求成员本地运行部署命令。

| Git 事件 | Cloudflare 行为 | 用户访问 |
| --- | --- | --- |
| 成员分支推送／更新 PR | 对纳入构建的仓库分支执行检查、构建并生成预览版本 | PR 或分支预览地址 |
| PR 合入 `develop` | 自动构建集成预览 | 团队联调入口 |
| 发布 PR 合入 `main` | 自动检查、构建并部署正式版本 | 固定 `workers.dev` 网址；自定义域名可后配 |
| 检查或构建失败 | 本次发布失败，保留上次成功的正式版本 | 正式地址继续可用 |

首次由仓库／Cloudflare 账号管理员完成一次配置：

1. 在 Cloudflare 创建 Workers 项目，授权访问 `zoran-sid/TaleLoom`，启用 Workers Builds Git 集成。
2. 设置生产分支 `main`，启用 `develop` 和成员开发分支的非生产构建／版本预览，确认预览链接可访问。
3. 配置仓库根目录、固定工具版本和构建输出目录。新增项目采用 Cloudflare CLI `cf`；当前参数、命令和生成目录见 [部署指南](cloudflare-deploy.md)。
4. Cloudflare 构建阶段依次执行 Python 测试、剧本校验与回放、网页构建和部署预检；全部成功后才执行对应环境的部署／预览发布。真实浏览器测试在 GitHub Actions 的 Ubuntu runner 执行，避免 Cloudflare 的系统依赖安装权限限制。合入 `develop`／`main` 前须确认全部 GitHub 检查通过，并在正式开通时配置为分支保护的必需检查。Cloudflare 原生构建不会等待 GitHub；直接部署功能分支时，两处检查结果分别确认。
5. 生产部署凭据仅由 Cloudflare 构建环境管理；网页产物只包含游戏运行文件、剧本和素材。保留 `main`／`develop` 现有 PR 审阅与保护流程。
6. 通过一次真实成员分支更新、一次 `develop` 集成及一次 `main` 发布验证整条链路；记录部署 URL、对应提交与失败构建保留旧版的结果。

这一次账号连接完成后，成员按现有分支／PR 流程推送代码即可。首次开通状态、项目名称、URL、版本限制与实际构建结果必须以真实配置为准，不能在配置前记录为已部署。

## 7 里程碑与验收证据

| 阶段 | 完成条件 |
| --- | --- |
| M1 共享契约 | 可运行快照／会话接口、插件动作描述、存档数据边界、固定样例；已有测试继续通过 |
| M2 桌面闭环 | VS Code 启动弹窗；两个序章全部结局可通过点击到达；存读档与错误提示可用；Windows／macOS 实机检查 |
| M3 浏览器核心 | 同一 Python 核心在 Pyodide 通过序章回放；与桌面在相同动作及随机状态下得到相同游戏状态／结局；确认运行时资源满足托管限制 |
| M4 网页与存档 | 桌面／手机宽度下可完整游玩；刷新后可恢复存档；桌面与网页 JSON 存档互通；加载／存储失败可恢复 |
| M5 自动发布 | 推送分支得到预览；合入 main 自动更新固定地址；失败构建不覆盖正式版；按相同发布链路验证扩写后的两个剧本 |

实现 PR 写实际测试与演示结果。需求表中新需求在取得对应证据前保持“计划中”。

## 8 技术依据

以下官方资料于 2026-11-07 至 2026-11-08 核对；架构方案由本项目据此选择，项目兼容性仍由 M3 验证。

- [Python Tkinter](https://docs.python.org/3/library/tkinter.html)：桌面窗口与 Tcl/Tk 安装前提。
- [Cloudflare Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/)：托管 HTML、CSS、图片与其他静态文件。
- [Cloudflare Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/)：连接 GitHub 后按推送自动构建和部署。
- [Cloudflare Build branches](https://developers.cloudflare.com/workers/ci-cd/builds/build-branches/)：生产与非生产分支构建配置。
- [Pyodide Web Worker](https://pyodide.org/en/stable/usage/webworker.html)：浏览器后台运行 Python，避免阻塞界面。
- [Pyodide Python compatibility](https://pyodide.org/en/stable/usage/wasm-constraints.html)：浏览器运行时与标准 Python 的差异。
