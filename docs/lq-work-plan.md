## 首个存档 PR 应覆盖的问题

当前桌面 `load_game()` 与临时网页 `LegacySession._decode()` 存在两套不同严格程度的校验。以合法存档为基础逐项修改，本次复现桌面读档会成功返回以下异常数据：

| 输入 | 应补的规则 |
| --- | --- |
| `save_version: true` | 严格整数版本检查，避免 `True == 1` |
| 内部 `state.story_id` 与当前剧本不符 | 外层和状态内部 ID 都匹配当前剧本 |
| `state.turn: -1` | 非负整数回合，排除布尔值 |
| `state.vars: []` | 字典资源，字符串键和整数值 |

应先写失败测试再修复，并覆盖正常往返、缺字段、坏 JSON、未知场景/物品、结局一致性、跨剧本、指纹变化提示及可变引用隔离。“读档接受异常数据”不等于每种数据都会立即崩溃；当前基线通过也不代表上述边界已受保护。

桌面存储继续保留原子替换。预期存储失败统一转换为 `StorageError` 等约定错误，由界面展示。CLI 目前会解析但忽略存档槽参数，多槽功能需与 ZRS 完成实际接入后才能勾选完成。

## 文件范围与集成规则

常规归属：`taleloom/save.py`、`taleloom/replay.py`、`web/storage/`、`stories/deep_space/`、`tests/lq/`。

- 改 `legacy_session.py`、临时网页、CLI、CI 或集成/浏览器测试时，在 PR 写清影响并请求相应负责成员核对；不代写其认可。
- `SaveStore` 只存取数据；会话/编码器负责格式和状态校验。槽元数据的展示方式与 ZRS 对齐，若要改共享协议则按 contract PR 流程同步所有调用和测试。
- 恢复成功使旧动作失效；失败保留会话/旧档；查看快照不推进回合、不触发自动存档或随机事件。
- 探索器的随机种子与剧情随机状态分开；存读档后继续的结果应与不中断执行一致。有限随机探索不等于穷尽所有输入。
- 单元测试用迷你剧本；真实两个剧本通过系统/集成入口接入 CI。探索失败必须使检查失败，不能捕获异常后当作成功。
- LQ 的常规审阅人为 ZQO；LQ 按轮换审阅 ZRS 的 PR。PR 保留真实验证和 AI 使用/人工核验说明。
